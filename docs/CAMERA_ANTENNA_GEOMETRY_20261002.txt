AGROROB: ZED CAMERA, ROBOT AND GNSS ANTENNA GEOMETRY
Evidence summary dated 2026-10-02
=================================================

PURPOSE AND EVIDENCE LIMITS

This document collects the geometry information found in local source code,
archived robot configuration and field-test analysis. It includes the full
geometry summary given in the conversation, its sources and qualifications.

We have substantial geometry information, but NOT a fully measured,
uncertainty-qualified 3D camera-antenna calibration. Some numbers are configured
dimensions, some are inferred from recordings, and some are navigation
simplifications. No fresh physical survey, live robot TF inspection or robot
SSH session was performed for this geometry review. No robot code was changed.

Numerical precision in a configuration or matrix is not measurement accuracy.
The listed files describe the inspected local/archived state, not a guarantee
that the physical September/October robot mounting has remained unchanged.


1. COORDINATE SYSTEMS AND ROBOT REFERENCE POINT
---------------------------------------------

Robot/body axes:
  X = forward; Y = left; Z = up.

Left optical camera axes:
  X = right in the image; Y = down; Z = forward through the lens.

Global ENU axes:
  X = east; Y = north; Z = up.

These follow ROS REP-103. Source [1]. The bag-derived manifest also explicitly
records optical and physical rear-axle conventions. Source [16].

Agrorob's base_link reference changes with steering mode:

  CAR: base_link uses the rear-axle reference.
  4WS: base_link uses the wheelbase centre, 1.50 m forward of the rear axle.

This changes reported coordinates, not the physical sensor mounting. For a
calibration record, use a fixed physical rear-axle reference and explicitly
define its vertical origin, rather than relying only on the mode-dependent
base_link name. Source [2].

Vertical-reference warning: the camera's 1.31 m is documented as above ground,
while navigation files describe their origin as the rear axle. The inspected
records do not independently establish a surveyed 3D origin relating ground,
axle hub height and antenna reference points. Do not silently interpret all
configured Z values as a measured common physical datum.

3. LEFT LENS VERSUS ZED MOUNTING FRAME
------------------------------------

The left optical origin is NOT at zed_camera_link.

Stored internal chain, translations in each parent's axes:

  zed_camera_link -> zed_camera_center:
    [0.000, 0.000, +0.015] m

  zed_camera_center -> zed_left_camera_frame:
    [-0.010, +0.060, 0.000] m

  zed_camera_center -> zed_right_camera_frame:
    [-0.010, -0.060, 0.000] m

  left camera frame -> left optical frame:
    No translation; axis rotation only.

The static publisher stores the optical rotation quaternion in XYZW order as
[0.5, -0.5, 0.5, -0.5]. The equivalent optical-to-camera-body rotation matrix is:

  [ 0   0   1 ]
  [-1   0   0 ]
  [ 0  -1   0 ]

The mount configuration documents the internal values as observed in the
July 3 ZED bag TF. This review inspected that documentation and code; it did
not newly extract the complete TF tree from the original raw camera bag.
Sources [3], [8], [9].

Using the internal offsets and 20.17 degrees downward pitch gives these
calculated left optical origin positions in the CAR reference:

  VO zero-yaw model:
    [3.175785364, 0.060000000, 1.327528173] m

  Newer mapper +0.130281398-degree yaw model:
    [3.175648945, 0.059990261, 1.327528173] m

These are derived coordinates, NOT measurements accurate to nine decimals.
The calculation rotates the internal [-0.010, +0.060, +0.015] m offset by the
mount rotation before adding the mount translation [3.18, 0, 1.31] m.

In 4WS, subtract 1.50 m from the X coordinates. For example, the mounting
frame becomes [1.68, 0, 1.31] m. Physical camera-to-antenna geometry should not
change merely because this software reference point changes.


4. CAMERA ORIENTATION: PITCH, YAW AND ROLL
---------------------------------------

PITCH

  Original nominal mount:       24.50 degrees downward.
  July mosaic correction:      -4.33 degrees.
  Corrected/configured pitch:   20.17 degrees downward.

The July 10 crop-mosaic analysis compared overlapping near- and far-range
ground projections. It adjusted pitch/yaw to reduce their disagreement. The
report describes along-track disagreement reducing from approximately 65 cm
to 5 cm and lateral disagreement from approximately 4.3 cm to 1.7 cm.

This is useful image-based calibration evidence, not an independent surveyed
6-DoF calibration with angular covariance. The original experiment used the
July 3 recording. Its method and interpretation limits are in source [10].

Current VO and VSLAM mount YAML files use 20.17 degrees. Some older README
text and standalone code defaults still say 24.5 degrees. Loading the intended
configuration therefore matters. Sources [3], [8], [9], [22].

YAW

  -1.40 degrees:
    Older mosaic calibration relative to RAW antenna-baseline heading.

  +0.130281398 degrees:
    Newer mapper's estimate relative to physical robot forward, after removing
    the inferred antenna-baseline heading bias.

  0 degrees:
    Current VO mount transform's assumed yaw.

The newer mapper explicitly uses:

  Antenna baseline yaw bias = atan2(0.037, 1.385)
                           = 1.530281398 degrees.

  Camera yaw relative to robot = -1.40 + 1.530281398
                               = +0.130281398 degrees.

Therefore -1.40 and +0.13 degrees are NOT interchangeable: their heading
references differ. Applying both corrections indiscriminately would count
the same heading effect twice. Source [11] explains the conversion.

ROLL

The current VO mounting transform applies pitch only; its mounting roll and
yaw are effectively zero. The newer mapper uses the small yaw above and the
same pitch. An independently measured mounting roll and its uncertainty were
not found. Source [9].

Dynamic body roll/pitch are distinct from fixed camera mounting angles. A
correct fixed transform does not, by itself, account for robot tilt on terrain.


5. ANTENNA GEOMETRY EVIDENCE AND IMPLEMENTATION LIMITATIONS
--------------------------------------------------------

Configured antenna separation is 1.385 m. Older defaults containing 1.69 m
must not be treated as the current measured baseline. Historical baseline
analysis is available in source [21]; current geometry is in source [4].

The May 13 analysis inferred lateral antenna misalignment from the difference
between antenna-baseline direction and straight-driving direction. It reports:

  Selected straight-driving samples: 1,315.
  Baseline-versus-motion angle: +1.55 degrees.
  Reported 95% interval: +/-0.10 degree.
  Equivalent front-antenna lateral offset: +3.7 cm (left).
  Reported 95% interval: +/-0.3 cm.

These are the historical report's estimates, not freshly recomputed confidence
intervals or a tape measurement locating both antennas independently relative
to the chassis. They do not include every possible systematic error, including
body/motion misalignment. Attribution specifically to the FRONT antenna also
depends on the rear antenna/body reference assumptions. Source [12].

A later May 20 analysis noted that one run was consistent with about +4.3 cm
instead of +3.7 cm. It did not recommend retuning because of run-to-run
variability. Source [13].

IMPLEMENTATION INCONSISTENCY

The localization heading calculation uses gps_rover_y_offset_m = 0.037 m.
However, the antenna TF publisher assigns BOTH antennas the rear antenna's
Y and Z offsets. Its front-antenna TF does not include the 3.7 cm lateral
offset used by the heading calculation. With the inspected configuration,
both antenna TF heights are zero. Sources [2], [4], [23].

Consequently, a navigation TF tree alone is not a complete as-built 3D antenna
survey, even if localization behaves acceptably in planar operation.


6. EXISTING CAMERA-TO-PRIMARY-ANTENNA TRANSFORM
--------------------------------------------

The AgroMap robot profile contains T_camera_primary_antenna, mapping a point
expressed in the PRIMARY/REAR ANTENNA frame into the RECTIFIED LEFT OPTICAL
CAMERA frame:

  p_camera = R_camera_antenna * p_antenna + t_camera_antenna

Stored homogeneous transform (translation units: metres):

  [ 0.002273837398  -0.999997414828   0.000000000000   0.053496825042 ]
  [-0.344805866506  -0.000784034501  -0.938673691819   2.230807314490 ]
  [ 0.938671265186   0.002134391345  -0.344806757891  -2.222902965596 ]
  [ 0                0                0                1              ]

Configured frame names:
  world:             map
  camera:            zed_left_optical
  primary_antenna:   gps_moving_base_phase_center
  secondary_antenna: gps_rover_phase_center

These names express intended semantics; naming a frame "phase_center" is not
itself evidence that its reference point was surveyed or antenna phase-centre
offsets were accounted for.

Declared translation uncertainty:
  extrinsic_translation_sigma_m = [0.10, 0.10, 0.10] m.

The corresponding example profile describes these as one-sigma uncertainties
in the optical camera axes. They are declared prior uncertainty, not measured
calibration residuals or a demonstrated bound on all systematic errors.

Recorded provenance:
  method: rough tape measurement plus configured mount rotation
  status: rough prior; never silently treated as calibrated

Source [14], uncertainty description also [24].

IMPORTANT NUMERICAL CROSS-CHECK

I reproduced the stored matrix using:
  - camera mount [3.18, 0, 1.31] m;
  - pitch 20.17 degrees and yaw +0.130281398 degrees;
  - the internal ZED offsets listed above;
  - rear antenna at [0.32, 0, 0] m.

Its inverse places the camera origin relative to the primary antenna at:
  [2.855648945, 0.059990261, 1.327528173] m.

The implied lever-arm length is 3.149708047 m.

This approximately 3.150 m lever arm incorporates the ZERO ANTENNA HEIGHT
assumption. It is NOT independent evidence that the true 3D antenna-to-camera
distance is 3.150 m. Nor does the matrix provide an independent measurement
of antenna-frame orientation.

Using a common ground-referenced origin, the body-frame vector from the LEFT
CAMERA to the REAR ANTENNA would instead be approximately:

  [-2.85565, -0.05999, actual_rear_antenna_height - 1.32753] m.

The missing antenna height directly changes the 3D transform. A horizontal
camera/antenna displacement alone is not sufficient for full 3D georeferencing.

Related mapping handoff [20] already identifies rough lever geometry and
missing roll/pitch evidence as unresolved accuracy limitations. A previous
calibration-only cross-validation did not justify silently introducing a lever
correction, time offset or stereo scale change.

HD1080 full-precision stored values:
  fx = fy = 1118.6947021484375
  cx = 964.8566284179688
  cy = 559.3102416992188

Stereo baseline from projection calibration:
  B = 0.1198462504 m (approximately 119.846 mm).

The July 3 right projection matrix records Tx = -134.0713653564453 pixel*m.
Using B = -Tx/fx gives 0.11984625036568344 m. Source [16].

The internal TF separation is rounded to 0.120 m. Its difference from the
projection-derived baseline is approximately 0.154 mm; numerical rounding
is not an independent uncertainty estimate.

HD720 is NOT simply a two-thirds scaling of HD1080. The HD720 configuration
explicitly records a different/wider-FoV readout. The small difference between
July and August HD720 values also supports using each recording's own
CameraInfo rather than assuming an immutable generic file.

The listed D coefficients are zero and rectification matrices are identity
for the inspected rectified-image records/configuration. This does NOT imply
the raw physical lenses have zero distortion. Raw-camera calibration must not
be inferred from already-rectified CameraInfo.

Configured frame rate is 15 Hz; that is a configuration value, not a claim
about every recording's measured delivery rate.

Sources: HD1080 [15], July 3 camera-info manifest [16], HD720 config [17],
August 27 actual camera-info capture [18].


8. ISAAC SIM GEOMETRY USES A DIFFERENT ORIGIN
------------------------------------------

Current inspected simulator camera mount:
  translation:    [1.6611, 0.0, -0.243] m
  roll/pitch/yaw: [0.0, 20.17, 0.13] degrees

The simulator configuration explains:
  - rear axle is at X = -1.5189 m relative to its URDF base_link;
  - simulation base_link settles about 1.553 m above the ground;
  - camera X = 3.18 - 1.5189 = 1.6611 m;
  - camera Z = 1.31 - 1.553 = -0.243 m.

These compensate for the simulator chassis origin and assumed settled height.
They are intended to represent the same rear-axle/ground camera placement,
not a second independent physical measurement. Do not copy these coordinates
directly into a physical rear-axle calibration without changing the reference.
Source [19].


9. WHAT IS MISSING FOR DEFENSIBLE FULL-3D CALIBRATION
--------------------------------------------------

The inspected records did not establish an independent, dated measurement of:

  1. Both antenna reference-point heights and each antenna's chassis XYZ.
  2. Whether physical measurements refer to antenna housing, mounting/antenna
     reference point or electrical phase centre, including applicable offsets.
  3. A surveyed common origin tying ground, rear axle and all sensor frames.
  4. Camera mounting roll, and defensible uncertainty on mounting pitch/yaw.
  5. Measurement uncertainty for the 3.18 m, 1.31 m and 0.32 m dimensions.
  6. A dated record proving these values apply to the unchanged September/
     October robot mounting.
  7. A complete validated 6-DoF camera-to-antenna calibration covariance.

The May 13 statistical intervals, the 10 cm mapping prior and the image-based
pitch/yaw correction are different kinds of evidence. They must not be combined
or described as if they were one survey-quality calibration certificate.

BOTTOM LINE

We have useful nominal mounting geometry, recorded stereo calibration,
image-based orientation estimates and a deliberately rough camera-antenna
prior. The largest gaps for full 3D accuracy are antenna heights/reference
points, a consistent yaw convention, and defensible uncertainty. The existence
of a precise-looking matrix or a healthy RTK fix does not close those gaps.
